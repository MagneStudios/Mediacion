### P3 — Negociaciones (aditiva)

  - Enums `materia_acuerdo` (tenencia, alimentos, bienes, otro) y `estado_negociacion` (borrador, activa, acordada, cerrada, terminada).
- Tabla `negociaciones` (caso_id → casos CASCADE, materia, estado, round, round_negotiating) con **UNIQUE (caso_id, materia)** — un caso puede cerrar varios acuerdos, uno por materia.

- RLS `negociaciones_all` — una sola policy `FOR ALL` con `is_part_of_case(caso_id) OR is_admin()`; grants a authenticated/anon/service_role/postgres (settings/helpers).
- QA: reset 40/40; smoke 88/88 (trigger set_updated_at 21→22); validate_rls 54/54; lint 0.

- Nueva columna única por caso hoy: `caso_partes_caso_usuario_unique` y `respuestas_propuesta_unique` (estaban pendientes de backfill del 09-05; se incorporan a la verificación de smoke).

### P5 — Versionado de acuerdos (aditiva)

- Decisión §5.2: versionado con intención explícita — **no** se agrega miembro a `estado_acuerdo` (el front no renderiza "reemplazado" como "borrador" en sus ternarios).
- `acuerdos`: `version INT NOT NULL DEFAULT 1`, `supersedes_agreement_id UUID → acuerdos(id)` (auto-ref, sin CASCADE; append-only de hecho), `vigente BOOLEAN NOT NULL DEFAULT true`, `valid_from TIMESTAMPTZ NOT NULL DEFAULT now()`.
- `CREATE INDEX idx_acuerdos_negociacion_vigente ON acuerdos (negociacion_id, vigente)` — "acuerdo vigente de la negociación".
- QA: reset 42/42; smoke 92/92 (4 checks de columnas + índice); validate_rls 61/61 (INSERT con defaults de versionado pasa y RLS sigue resolviendo por negociación); lint 0; db-types typecheck verde; tsc raíz sigue rojo solo por el flag P4 (esperado).
