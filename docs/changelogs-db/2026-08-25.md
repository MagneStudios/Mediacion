# Changelog — Proyecto Mediación (DB)

## 2026-08-25 — Custom Access Token Hook + Fix Auth 500

> Resuelve el 500 en `POST /auth/v1/token` causado por un `custom_access_token` hook mal implementado y usuarios dev creados sin campos requeridos por GoTrue.

### Problema

- El hook `custom_access_token` estaba habilitado en el Dashboard de Supabase Cloud pero la función no existía → GoTrue retornaba 500 en cada intento de login → auth completamente rota.

### Causa raíz (3 bugs encadenados)

1. **Función inexistente**: El hook apuntaba a una función que no estaba en la DB → 500 inmediato.

2. **Ruta del evento incorrecta**: Mi versión inicial leía `event -> 'session' -> 'user' ->> 'id'` pero la estructura real del hook es `event ->> 'user_id'` (top level). El `user_id` siempre era NULL → `NO_DATA_FOUND` → 500.

3. **Claims incompletos**: Devolvía solo `{rol, estudio_id, nombre_completo}` sin preservar los claims originales (`sub`, `role`, `exp`, `iat`, etc.) → JWT roto aunque el login devolviera 200.

### Fix: custom_access_token (migración `20260825000000`)

- Función `public.custom_access_token(event jsonb) RETURNS jsonb`
- `SECURITY DEFINER`, `SET search_path = public`
- Lee `event ->> 'user_id'` (ruta correcta del hook)
- Copia `event -> 'claims'` y **agrega** los custom claims (patrón oficial Supabase)
- Claims inyectados: `rol` (rol_usuario), `estudio_id` (uuid), `nombre_completo` (text)
- `EXCEPTION WHEN NO_DATA_FOUND` como respaldo para usuarios nuevos
- `GRANT EXECUTE TO supabase_auth_admin`

### Fix: Dev users — token columns + auth.identities

- `tmp/test_00_dev_users.sql` actualizado:
  - Columnas token (`confirmation_token`, `recovery_token`, `email_change_token_new`, `email_change`, `email_change_token_current`, `reauthentication_token`) → `''` (empty string, NO NULL). GoTrue las escanea como Go `string` y NULL causa 500.
  - INSERTs en `auth.identities` para cada usuario (provider='email', identity_data con sub/email/email_verified). Sin esta fila, GoTrue no puede autenticar al usuario.

### Lecciones aprendidas

- **GoTrue requiere `auth.identities`**: Insertar solo en `auth.users` no es suficiente. GoTrue busca en `auth.identities` para autenticar.
- **Columnas token NO pueden ser NULL**: `confirmation_token`, `recovery_token`, etc. deben ser `''` (empty string). GoTrue las escanea como `string` en Go; NULL causa `Scan error`.
- **Patrón oficial de claims**: copiar `event->'claims'` → modificar → devolver. NO reemplazar claims enteros, porque GoTrue necesita los originales (`sub`, `role`, `exp`, etc.).
- **Evento del hook**: `event->>'user_id'` (top level), NO `event->'session'->'user'->>'id'`.
